# v0.7 — Review Provenance, Benchmark Governance and Reproducible Corpus Releases: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:executing-plans (or subagent-driven-development) to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Close the five verified v0.6 review-workflow defects (discarded rationales, discarded submission/packet provenance, unenforced reviewer roster, unbound adjudications, unsafe batch writes) and add a deterministic offline corpus-release system.

**Architecture:** Pure semantics in `src/benchmark/` (`provenance.ts`, `batch.ts`, `release.ts` added; `review.ts`, `scoring.ts`, `report.ts`, `validate.ts`, `types.ts` extended), filesystem and flags in `scripts/`. One shared adjudication-binding resolver serves disagreement reporting and scoring.

**Tech Stack:** Node 24, TypeScript ESM (`.ts` specifiers, `type: module`), `node:test`, `node:crypto`, `node:fs`, `node:path`. No new dependencies.

**Spec:** `docs/technical/BENCHMARK_PROVENANCE_AND_CORPUS_RELEASES.md` (committed `3828431`). Read it with this plan; the spec argues the semantics, this plan sequences them.

## Global Constraints

- Local and offline only: no network, no database, no provider, no crawling, no remote publishing, no auth, no billing.
- `src/benchmark/**` may import `src/core/**` and `node:` builtins only (`scripts/check-boundaries.ts`). All filesystem IO stays in `scripts/`.
- No clock inside `src/benchmark`. Every timestamp is human-supplied and stays marked as such.
- `accuracyClaimable: false` is hard-coded in the audit and in every release manifest. Readiness is never an accuracy claim.
- Hashes are integrity checks. They authenticate no reviewer and prove no material genuine.
- Preserve `benchmark-case-v1`/`benchmark-case-v2` reading and `benchmark-report-v2` output. New case fields are optional and additive; `AgreementRow.status` enum values are never added or renamed.
- Never fabricate a case, reviewer, timestamp, label, rationale, permission or roster entry. Refuse rather than fill.
- ADR-025's `evidence-aggregation-v1` default is untouched. ADR-026 stays Proposed. ADR-027 is recorded Proposed, not accepted on the owner's behalf.
- Node 24; PowerShell on Windows (`;` not `&&`). `*.md` is prettier-exempt; `.gitattributes` forces LF.
- Test counts are re-measured by glob for every documentation claim.
- Do not merge the PR. Do not force-push. Push only after `npm run check` is green.

## Owner Safeguards (binding on every task)

1. Legacy unbound adjudications stay readable but are explicitly identified as `UNBOUND` and are never silently treated as verified in releases.
2. Merge is genuinely atomic across the whole batch and the filesystem output by default; `--allow-partial` is explicit and reports every accepted and rejected item.
3. Release manifests are independent of timestamps, absolute paths, machine identity and execution environment.
4. Reviewer rationale, timestamp and packet provenance survive every stage (merge → report → audit → release → re-read).
5. One shared adjudication-binding resolver for disagreement reporting and benchmark scoring.
6. Historical report output and v1/v2 case compatibility preserved.
